# Harmony v2

The Go and raylib client for a Harmony server. The server is unchanged: v2 speaks the protocol it already has, so both clients can share a voice channel. The rules this code follows are in `../.claude/rules/v2-client.md`; the study behind the project is in [FEASIBILITY.md](FEASIBILITY.md).

## Run

Needs Go 1.27.4. Video (decode, encode, screen and camera capture) uses the system's own codecs and capture APIs, called without cgo; nothing else has to be installed.

```sh
dev/stack.sh &                          # a local server and MediaMTX; accounts alice and bob, password hunter22
go run -tags nocgo ./cmd/harmony2 -server http://127.0.0.1:18280
```

`-tags nocgo` is required: raylib is loaded from its embedded library so it does not clash with the sound card library's miniaudio. On Windows the sound card is WASAPI called without cgo (`internal/audio/wasapi_windows.go`), so no C compiler is needed, and a build meant to be double clicked adds `-ldflags "-H=windowsgui"` so that no console window opens (`dev/build.sh` and the release do). `-screenshot out.png` writes the window and exits; `-tone 440` sends a tone as the microphone; `-width`/`-height` size the window.

`cmd/h2probe` is the same client without a window, to try voice and screen share between two instances.

## Layout

```
cmd/harmony2         the window
cmd/h2probe          the client without a window
internal/shell       window, frame loop, which screen shows
internal/screens/*   one package per screen (and per dialog or flow)
internal/conntest    the connection test's steps
internal/emoji       the emoji list and shortcodes
internal/ui/emojitext  emoji clusters and the system emoji font
internal/clip        sound clip decoders
internal/chat        text channel messages, who is typing, link cards, uploads
internal/markdown    the message markdown subset
internal/filedialog  the system's open-file dialog
internal/ui/widget   reusable components and layout
internal/ui/paint    drawing in CSS pixels: shapes, text (variable fonts), icons
internal/ui/raw      raylib calls that allocate nothing (the window and input, every frame)
internal/ui/theme    the Electron client's palettes
internal/ui/redraw   asking for the next frame; the window sleeps when nothing asked
internal/i18n        the Electron client's translations
internal/app         sign in, voice channel, screen share
internal/hclient     the server's HTTP and WebSocket protocol
internal/media       WebRTC with Pion; Opus with gopus
internal/audio       mixer and sound card
internal/video       H.264 capture, encode and decode on the system's own codecs (internal/video/native: VideoToolbox, Media Foundation, VA-API), plus the synthetic bars and test sources
dev/                 stack.sh, spec-shot.mjs and imgdiff.go (compare a screen with Electron's), export-locales.mjs
```

## Porting a screen

1. `node dev/spec-shot.mjs /tmp/el.png [--steps "js"] [--settings '{...}']` captures the Electron screen at 1180×800, 2× (the default zoom is 115%).
2. Build the screen from components; add a component to `ui/widget` when one is missing.
3. `harmony2 -screenshot /tmp/go.png`, then `go run dev/imgdiff.go go.png el.png` for the share of differing pixels, `... align x y w h` for an element's offset, `... x y w h scale out.png` for a side-by-side crop.

## Ported

- Looks: profile pictures and banners everywhere a face is drawn (decoded at the size drawn and cached on disk by hash, initials until loaded), name font, colour (solid, gradient, rainbow, moving only while drawn) and role colour, the profile card (click a name or picture), banner strips behind member and voice rows, and Settings > Profile (picture and banner with the crop window `screens/imageedit`, dimming, name font and colour, join sound). Not yet: animated GIF pictures play only as their first frame.

- Connect: server address and account steps, with the saved account filled in, and the Options section: the connection test (a dialog: server, media server, signalling port, STUN) and Encode on the GPU (saved, used once screen share has a screen). The clip buffer is left out: v2 has no clips. The saved-servers menu under the server chip (search, status dots, switch, forget, add a server, back to my servers). Forgot password (the three questions, then a new password, then signed in). Saved sign-in: the session token, the remembered password and the server password are kept in the system's secret store (`internal/secrets`: Keychain, Windows data protection, Secret Service), a launch or a pick from the rail goes straight in when the saved session is good (Security page toggle), an expired session signs in again with the remembered password, "Not you? Sign out" revokes the session. Connection: the socket is redialled with backoff and everything the hello carries is read again, the voice channel, camera and share are rejoined, a "Reconnecting..." note shows meanwhile, a kick, ban or expired session returns to this screen with the reason; notes in the channels screen go away after nine seconds.
- Channels screen: top bar, channel list with who is in each voice channel, the voice room, the call panel (leave, camera, share screen, soundboard), the member list with search and presence, and your own strip (mute, deafen, device menus, settings). Joining a voice channel starts the sound card and microphone, leaving stops them. The device menu (arrow beside mute and deafen, or right-click): choose the device and set its volume. The soundboard: find a clip by name, play the server's clips for the channel, and as an admin add, stop, rename (name and emoji), delete (with a question) and move clips left or right, live for everybody. The camera: the Native size and rate (the biggest picture the camera holds at 30 fps, asked of the system), a switch-camera button in the call panel when there is a second camera, a camera that opens black is opened again (up to twice), "Fix black video" in Settings opens every watched stream again, and the camera's messages (unplugged, could not open, quality not possible) show in the hint banner or under the devices. The camera publishes the default camera (360p, 24 fps); nobody sees video yet because the call screen is not ported. Settings (gear): Profile, Security (password, recovery questions), Appearance (language, palette, interface size, link previews), Voice & video (devices, camera quality, video encoder and decoder backend, input volume, input sensitivity with a live meter and an automatic setting, automatic gain control, echo cancellation (the system's own, `internal/echo`: Apple's voice processing unit on a Mac, which then plays and records instead of the sound card streams; the Voice Capture DSP on Windows; PulseAudio and PipeWire's echo-cancel module on Linux, loaded through libpulse; `dev/echomeasure.go` measures it; only the Mac has been run), noise suppression and strong noise suppression (RNNoise, in Go), a button that reopens black pictures, open streams automatically, pause cameras while hidden, GPU encode) and Sounds (master volume, voice channel sounds, members' own join sounds, the mention sound, sound effects volume; the cues are synthesised, nothing is shipped); every control applies at once. Left out because v2 has no such feature: profile picture, banner, name font and colour, text size, picture in picture, camera background. The call screen (voice room with video): a grid of camera and share tiles, a focus layout with a strip, full window, closed tiles you can reopen, your own camera preview. Streams are watched on demand and decoded only at the size they are drawn. Channel groups (headings that fold, drawn in the list in order of position; a folded group carries its channels' mention count; folds last for the session, as in Electron) and unread state (bold names, an @ count from the server's own counts kept live from `message` and `channel:read`, the "new messages" divider, opening a channel at its first unread message, read marks sent as the log is shown) are in. Share audio (`native.StartAudioCapture`: ScreenCaptureKit on macOS, WASAPI loopback and process loopback on Windows, the default output's monitor through libpulse on Linux; Opus stereo 128 kbps on the share's own connection; the picker's sound rows and note, per-share volume and mute kept per person, "hear your own stream" where it cannot loop back; only macOS has been run). Not yet: picture in picture.
- Text channels: the log (history on demand, live messages, grouping, reply headers, scroll anchored to the end, a button back to it), message text with bold, italic (the system's own italic face, as the browser picks it), strike, code, links, @mentions, quotes, lists, headings and code blocks, pictures (click for a larger view, saved to Downloads), text files that show their first lines and unfold, other files as cards, link cards read by the server (a YouTube card opens the browser), who is typing (shown and sent), the box (grows to eight lines, Enter sends, Shift+Enter a new line), files from the + button or dropped on the window, with a progress bar, replying, editing and deleting your own. Reactions (strip, who reacted), the emoji picker (loaded in the background, only visible rows drawn), server custom emoji and :shortcode: text, colour emoji everywhere text is drawn (Apple Color Emoji verified; Windows and Linux code never run). Voice messages (record from the microphone, also while in a call, pause and send; play with waveform, seek and speed 1x/1.5x/2x; WebM Opus like the Electron client) and a player for plain audio files. Polls (the button beside the emoji picker makes one: question, description, picture, options, several answers, hidden voters, an end time; the card shows bars, counts, faces, your own choice, closes by itself at its end, votes change live, and View votes lists who chose what; private conversations are not ported yet; the end time is typed as `YYYY-MM-DD HH:MM`). Search, pins and stars: the box in the header with filter chips (from, in, has, mentions, dates, pinned), its list of filters and past searches, the answers beside the log with Filters and Sort and pages, a pinned strip and list (live, with the pin in the hover tools for those who may), your own stars kept in the settings file, and a jump to any message that loads the log around it and flashes it (Esc closes each panel). Forum channels (the list with title, first words, reactions, answers and age, pinned posts on top, Sort and Mentions, search or create a post, the New Post card with title, words, emoji and up to ten files; a post opens beside the list as a thread of the chat view with its title, OP mark and answers, searched, pinned, starred and replied to like a channel; pin and delete for those who may; live updates, read marks and @ counts; search results and stars jump into the post). Not yet: dragging the list's width, remembering the sort, wrapping a long post title in the header, locked posts and editing a title (the server has neither), pictures and files in the search, pin and star lists (they show the file's name), the hover preview of a file being dragged over (the window toolkit only reports the drop).
- Text editing and the composer: selection with the keyboard (shift, word and line moves with Alt or Cmd on macOS and Ctrl elsewhere), mouse drag, double and triple click, Select all, Copy, Cut, Paste, Undo and Redo in every field; message text in the log is selectable across messages (drag, double click a word, triple click a paragraph, Ctrl or Cmd+A and +C copy the rendered text) with a right-click menu (copy, open or copy a link, copy the message); the @ and # pop-up (people, roles, @everyone, channels), Up in an empty box edits your last message, Esc cancels a reply or an edit, long pastes become message.txt and a pasted picture or copied file becomes an attachment (macOS and Windows; Linux pastes text only); role and channel chips, @everyone and role chips show who was notified, replace the file of your own message, delete anybody's message with the permission after a confirm, link cards can be closed for good and a link to a picture shows the picture, videos open in the system player, GIFs play while shown. Not yet: IME composition drawn in the box (committed text arrives), animated WebP, playing YouTube in place.
- Private messages (the rail's first bubble, with an unread badge; right-click a member for "Send a private message"): the list with find, the conversation drawn by the channel chat's own rows (text, pictures, files, polls, replies, edit, delete, reactions, pins, voice notes), key states (recovery key, unlock, start over), safety number and verify, key-change and block banners, groups (create, people, rename, leave), clear and block. Not yet: search, stars, calls, typing and the "Message" notification in private conversations.
- Server dialog (gear in the top bar for anybody who may use a page; the pages each person sees follow their permissions, as in Electron): General (name, logo and banner through the image editor, door password and "No password at all", largest file and space for files, Music Buddy with the yt-dlp notice) and Badges (list, new badge with Create, name, description, emoji or picture, delete with confirmation), all live with a Saving/Saved line in the footer; server, roles and badges changes from other people update an open dialog at once.
- Server dialog, Roles page: the roles in hierarchy order with find and move up and down, and for the selected role the name, the look of its name (a colour with a picker, a moving gradient of two to four colours, or the rainbow, with its speed and a preview), administrator, every permission by group, the roles it may hand out and the badges it may award; every switch obeys what the signed-in person may grant (`hclient/rolerules.go`, tested), changes are sent as they are made, **Create** makes a new role and Delete asks first. - Server dialog, Members page: everybody on the server by rank then name with find, role chips and a crown or shield for the owner and super admins; the editor for the selected person has the roles as switches (obeying the hierarchy), the super admin switch for the owner, badges, Kick and Ban with confirmation (a ban is lifted from the same button), live with the realtime roster. - Desktop (`internal/desktop`, one package per OS feature, no cgo): global hotkeys (mute, deafen, camera, soundpad clips, push to talk; `internal/hotkey`: Carbon hot keys plus a listen-only event tap on a Mac, low-level hooks on Windows, X11 grabs or the GlobalShortcuts portal on Linux; a Mac needs Input Monitoring for push to talk with a bare key and for mouse buttons, nothing for combinations with Ctrl or Command; Wayland has no global keys except through the portal), the Hotkeys settings page with a recorder, your status per server (the dot on your picture opens online, idle, do not disturb, invisible; idle after five minutes without input anywhere on the computer, read from the system), desktop notifications for mentions and private messages while the window is not in front (not under do not disturb; a Mac's notification cannot be clicked without an app bundle), the tray or menu bar icon with its menu and the close button hiding the window into it, the Updates page (checks the project's GitHub release for `harmony2-<os>-<arch>`, verifies its SHA-256, replaces the program and restarts) and the Debug page (the log ring and a log file with samples; `internal/debuglog`).
